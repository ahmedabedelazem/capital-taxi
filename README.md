# تاكسي العاصمة | CAPITAL TAXI

منصة نقل ذكية مخصصة للعريش وشمال سيناء، بثلاث بوابات: العميل والسائق والإدارة.

## الحالة الحالية
هذه مرحلة تأسيس الواجهة والبنية الأمامية. لا يوجد حالياً ربط تشغيلي بقاعدة Firebase أو نظام توزيع رحلات حي؛ ولا تُعتبر أي ميزة تشغيلية مكتملة قبل تنفيذها واختبارها.

## التقنية
- Next.js App Router + TypeScript
- Tailwind CSS
- واجهة عربية RTL ومتجاوبة
- هوية Premium Dark Luxury

## التشغيل المحلي
```bash
npm install
cp .env.example .env.local
npm run dev
```
ثم افتح http://localhost:3000

## المسارات
- `/` الصفحة الرئيسية
- `/customer` بوابة العميل
- `/driver` بوابة السائق
- `/admin` بوابة الإدارة

## المصادقة الخادمية\n- `POST /api/auth/session`: يستبدل Firebase ID token بجلسة خادمية في Cookie من نوع HttpOnly لمدة خمسة أيام.\n- `DELETE /api/auth/session`: ينهي الجلسة بحذف Cookie.\n- `GET /api/me`: يتحقق من Cookie الجلسة أو Bearer ID token ويعيد هوية المستخدم ودوره الموقّع.\n- تُقرأ أدوار `driver` و`admin` من Firebase custom claims الموقعة فقط؛ لا يستطيع العميل تعيينها من الطلب.\n- يلزم إعداد `FIREBASE_PROJECT_ID` و`FIREBASE_SERVICE_ACCOUNT_JSON` كأسرار خادمية في بيئة التشغيل، ولا تضع بيانات حقيقية في Git.\n\n## الأمان
- التحقق من الصلاحيات يجب أن يتم على الخادم.
- لا تعدّل المحافظ أو العمولات من العميل مباشرة.
- قبول الرحلة يجب أن يكون ذرياً عبر Backend موثوق.
- لا تُعرض بيانات التواصل قبل الإسناد وفق سياسة واضحة.
- قواعد Firebase والبيانات الحقيقية خارج نطاق هذه المرحلة.


## طلب الانضمام كسائق واعتماد الإدارة
- `POST /api/driver/application`: يرسل طلب انضمام المستخدم المسجل كعميل، ويحفظه بحالة `pending` على الخادم.
- `GET /api/admin/drivers`: يعرض الطلبات المعلقة للإدارة المعتمدة فقط.
- `PATCH /api/admin/drivers/:uid/decision`: اعتماد أو رفض الطلب، مع سجل تدقيق وتحديث Firebase custom claims من الخادم.
- صلاحية السائق تتطلب claim موقّعاً وسجلاً خادمياً بحالة `approved` معاً.
- هذه المسارات مضافة للمستودع ولم تُنشر أو تُختبر على Firebase حقيقي بعد.
